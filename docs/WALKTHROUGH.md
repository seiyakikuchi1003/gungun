# 実機での通し確認（台本）

`npm run preview` で立ち上げた状態から、**上から順にそのまま操作すれば
アプリの全機能と DB の連動を一周できる**ように書いてあります。所要 20〜30分。

- 左のターミナルに Expo の QR、ブラウザに管理画面（http://localhost:3100）
- 「管理画面で見る」の欄は、操作したあと**ブラウザを再読み込み**すれば反映されます

## 準備：2アカウント用意する

わらしべ長者は相手がいないと成立しないので、**2人ぶん**必要です。

| 役 | 端末 | アカウント |
|---|---|---|
| **A（あなた）** | iPhone（Expo Go） | `metan@example.com` / `password` |
| **B（相手役）** | Mac のブラウザ（Expo で `w` を押す）または2台目 | `takusan@example.com` / `password` |

ログイン画面の下に **「● 実データ（Supabase）に接続中」** が出ているか先に確認してください。
出ていなければ実データではなくモックです（`.env` が読めていない）。

## 1. ログインとログインボーナス

| # | 操作（A） | 期待する動き | 管理画面で見る |
|---|---|---|---|
| 1-1 | メール＋パスワードでログイン | ホーム（森）に入る | ダッシュボード「ユーザー」が 6 |
| 1-2 | ホーム上部の肥料カードを見る | 残高が数字で出ている | ユーザー → めたん の「肥料」と一致 |
| 1-3 | 「受け取る」を押す | 肥料が増える。2回目は押せない | ユーザー → 肥料が増えている |

> 増える量は `app_settings.daily_login_bonus`（プレミアムは `daily_login_bonus_premium`）。
> **管理画面 → アプリ設定でその値を変えて、アプリを引き直すと変わります。** ここが「コードを触らずに調整できる」ことの確認になります。

## 2. 出品（タネを植える）

| # | 操作（A） | 期待する動き | 管理画面で見る |
|---|---|---|---|
| 2-1 | 右下の＋ → 「タネを植える」 | 出品フォーム | — |
| 2-2 | 写真を撮る／ライブラリから選ぶ | サムネイルが並ぶ | — |
| 2-3 | 商品名・カテゴリ・状態・説明を入れて出品 | 森に自分の木が生える | 商品 → 一番上に出る。**段 = 0**、状態 = 育成中 |
| 2-4 | ダッシュボードを見る | — | 「種（ツリーの起点）」が +1 |

Supabase の Table Editor だと `items`（`parent_id = null` の行）と `item_images`、
Storage の `item-images` バケットに実ファイルが入ります。

> **写真はここで初めて実データを通ります。** アップロードが失敗する場合は Storage の
> `item-images` バケットが 0006 で作られているかを確認してください（`npm run db:status`）。

## 3. 水やり（＝「ほしい！」）

ここが仕様の中心です。**B の商品に A が水をやる**という向きで確認します。

| # | 操作 | 期待する動き | 管理画面で見る |
|---|---|---|---|
| 3-1 | A で森から B の商品を開く | 商品詳細。ツリーが描かれる | — |
| 3-2 | 「ほしい！（水をやる）」を押す | 自分の交換候補を選ぶ画面 | — |
| 3-3 | 出す商品を選んで確定 | 肥料が減る。木に自分の枝がぶら下がる | ユーザー → A の肥料が減っている |
| 3-4 | B 側を再読み込み | 通知に「水やり」が来る | 商品 → 新しい行の **段 = 1**、ツリーが B の商品と同じ |

減る量は `app_settings.water_cost`。`fertilizer_ledger` に**マイナスの記録**が残ります。

**水やりできない4条件**もここで見てください（押せない・エラーになるのが正解）:

1. 自分の商品には水をやれない
2. 同じ商品に二度は水をやれない
3. 肥料が足りないときは押せない
4. ブロックしている／されている相手にはできない

## 4. 収穫

| # | 操作（B：木の持ち主） | 期待する動き | 管理画面で見る |
|---|---|---|---|
| 4-1 | 自分の商品 → 「収穫する」 | 水をくれた人の一覧 | — |
| 4-2 | 1人を選んで収穫 | 「収穫の輪」（一本道）が出る | ダッシュボード「収穫された種」が +1 |
| 4-3 | 選ばれなかった枝を見る | **苗木**として森に独立して残る | 商品 → その行の**段が 0 に戻る**（ツリーが自分自身になる） |
| 4-4 | 取引画面に移る | 輪の人数ぶんの取引が並ぶ | — |

`exchanges` に輪の人数ぶんの行ができます。**「大きい木ほど得」ではなく一本道**なので、
輪に入るのは選ばれた一直線の人だけです。

## 8. 退会（ここが一番壊れやすい）

**最後にやってください。** 取引相手の履歴が消えないことを確認します。

| # | 操作（A） | 期待する動き | 管理画面で見る |
|---|---|---|---|
| 8-1 | プロフィール → 設定 → 退会 | 確認のうえログアウトされる | ユーザー → めたん が消える |
| 8-2 | B でログインし直す | **取引履歴は残っている**。相手名が「退会したユーザー」 | 商品／通報の出品者欄が「—」になるが行は残る |

DB では 10 本の外部キーが `ON DELETE SET NULL` になっており、退会した人の行だけが
消えて**相手の取引・評価は残ります**（0009 で修正。`supabase/tests/0009_test.sql` で自動テスト済み）。

## うまくいかないときの切り分け順

1. `npm run db:status` — 0001〜0009 が全部 ✓ か
2. `npm run check:supabase` — テーブル・RPC・RLS・課金の安全性
3. ログイン画面のバッジが「● 実データ（Supabase）に接続中」か
4. 管理画面のサイドバー下に「● Supabase 接続中」が出ているか
5. 管理画面のログ … `.expo/admin-dev.log`

詳しい対処は [`DEVICE-PREVIEW.md`](./DEVICE-PREVIEW.md) の「つまずきやすいところ」。
