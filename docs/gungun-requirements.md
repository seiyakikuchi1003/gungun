## 1. コンセプト・世界観

わらしべ長者をベースにした **C2C物々交換アプリ**。不要品を出品し、それを「欲しい」と思った人が自分の不要品を出して交換の連鎖を作り、最終的に起点の人が欲しいものを手に入れる、というループを回す。園芸メタファーで表現する。

| メタファー | 機能的な意味 |
|---|---|
| 種を植える | 出品（わらしべの起点／木の根） |
| 水やり | 「欲しい・交換したい」の意思表示（＝子ノードとして自分の商品をぶら下げる） |
| 収穫 | 取引成立 |
| 肥料 | アプリ内ポイント |
| 木・枝 | 1つの種から連なった商品群（ツリー） |
| 元の種 | ツリーの根（起点の出品） |

基調は緑×オレンジ、マスコットはみかん。

## 2. コアデータ構造とツリーロジック（最重要）

### 2-1. 森＝複数の木
アプリ全体は「森」。各**種＝木の根（root）**。**水やり＝親ノードに子ノードを1つ足す操作**。同じ親に複数人が水やりすると枝分かれする。各ノードは親を1つだけ持つ（きれいな木構造）。

```
A（種）
├─ B      ← BがAに水やり
│  └─ D   ← DがBに水やり
│     └─ F ← FがDに水やり
└─ C      ← CがAに水やり（枝分かれ）
```

**データモデルは「親ID・ルートIDを持つノードのツリー」で持つ。** これがv1の設計の土台。

### 2-2. 2つの向き（重要）
- **水やりの向き**：子 → 親（BはAが欲しいからAに水やり）
- **品物（発送）の向き**：親 → 子（Aは自分の品を、水やりした子Bに渡す）
- 基本ルール：**「自分に水やりした人（子）に、自分の品を発送する」**

### 2-3. 収穫＝一本道の玉突き交換（確定）
起点Aが「Fが欲しい」と収穫すると、**AからFまでの一本道（A-B-D-F）だけ**が対象になり、輪になって一斉交換する。

- 品物：**A→B→D→F→A（輪）**
- 受け取り：A←F、F←D、D←B、B←A
- この道に乗った**全員が「1回発送・1回受け取り」**（人数分の閉じた輪）

### 2-4. 再ルート化＝植え直し・削除の共通処理（確定）
「あるノードが木から抜けたとき、その**子孫を新しい種（root）として独立**させる」——この1操作を、次の3ケースで共通に使う。

1. **収穫**：成立した道（A-B-D-F）のノードは消費され消滅。消費ノードにぶら下がっていた別の枝（例：C）は宙ぶらりんになるので、**その枝の先頭を新しい種として独立**（＝植え直し）。集まっていた水やりは保持される。
2. **植え直し**：収穫で選ばれなかった枝を、そのまま新しい種として再スタート。
3. **削除**：途中のノードを削除したら、削除ノードの子を新しい種として切り離す（上流はそのまま）。

```
削除の例： A → B → [C削除] → D → E
      ↓
      A → B（そのまま）　＋　D → E（Dが新しい種として継続）
```

> 実装方針：この「ノード離脱 → 子孫を新root化」処理を**共通関数として1本化**する。収穫・植え直し・削除を別々に実装しない。

### 2-5. 水やりの可否ルール（確定）
★2026-08-05 変更：判定範囲を「祖先ライン」から「木全体」に広げた。

- **1ユーザーは1つの木につき1回だけ水やりできる。**
- 対象が属する木（同じ root）に自分の商品が1つでもあれば**不可**。
  種でも、同じ木の別の枝でも、自分の子孫でも、**同じ木なら一律不可**。
- **自分が出品した種**には水やり不可（上のルールに含まれる）。
- **別の木**には水やり**可能**。
- **収穫で木が分裂したらリセット**：残った枝は新しい種（別の木）になるので、
  以前その木にいた人も、新しい木には改めて水やりできる。

### 2-6. 収穫の原則（確定）
- **1つの種（root）につき収穫は1回のみ。**
- 枝分かれ・残余は「新しい種」として独立するので、そちらは改めて1回ずつ収穫される。
- **同一ツリー内で複数の収穫が同時進行することはない**（v1対象外）。
- **収穫確定した商品は、他ルートから非表示・水やり不可**に制御する。

## 3. 収穫・発送・評価フロー（確定）

- 収穫ボタン押下で、**その道の全員に「発送義務」の通知**が飛ぶ。
- **「発送完了報告をしないと、自分は受け取れない」**フロー（発送しないと次に進めない）で滞留を防止。
- **評価は2回**：
  - 送った側 → **やり取りがスムーズだったか**
  - 受け取った側 → **商品の質はどうだったか**
- **送料は送る側（発送者）の負担**。
- 配送トラブル（未発送・未着）の対応ルールは **v1ではなし**。

---

## 4. 肥料（ポイント）システム

- **最初の種植え＝無料**。2つ目以降の出品／水やりには肥料が必要。
- **ログインボーナス：毎日40肥料**。
- 意図：無制限出品で交換が回らなくなるのを防ぐため、水やり（出品）を有料化。

> ⚠️ **金額・課金導線は「要相談（確定前）」**。現状のたたき台は「水やり＝200肥料／肥料切れ時は200円課金で1回出品／プレミアムでボーナス増量」。ただし「現状のままだとサービスとして成立しない」との認識があり、**課金設計はめたん様と別途詰めてから確定**する。実装は課金導線を差し替えやすい形にしておく。

## 5. 画面構成

ボトムナビ **5タブ**：① ホーム　② 掲示板　③ 収穫　④ プレミアム　⑤ マイページ
＋ ホーム派生：**通知**／**取引（やり取り）**（右上アイコン）

### ① ホーム
- 最上部：検索インプット「欲しいものを探してみよう」
- 右上：通知ベル＋取引アイコン（各未読赤ポチ）
- 自分の肥料（例：400肥料）＋ ログインボーナス（毎日40肥料）
- **みんなの種**：商品カード（サムネ＋タイトル＋カテゴリー＋出品者名＋水やり数）／「すべて見る」で一覧
- **ぐんぐんの楽しみ方**：種を植える → 水やりする → 収穫する の3ステップ
- ボトム上部に **「タネを植える（出品する）」ボタン常駐**

### 出品フォーム（種植え・水やり共通）
- 商品画像（複数枚、メルカリ式。先頭がサムネ、詳細ではカルーセル）
- 商品名 / 商品説明 / カテゴリー選択 / 商品の状態
- 商品詳細ページにコメント機能

### 商品詳細
- 商品写真：複数枚カルーセル、タップで拡大
- 商品名・カテゴリー、いいね／お気に入り（一覧からも押せる）
- 出品者：アイコン・名前・評価数・出品数 → プロフィールへ（※ランク表示はv1対象外）
- **元の種（つながっている種）**：木全体の商品件数を表示
- **植えている人が欲しいもの**：起点の種植者が欲しいものリストを公開（プレミアム機能／課金と合わせて要相談）
- **「この商品に水やりする」ボタン**
- 元の種タップ → 種の詳細（木全体の商品数／つながっている商品一覧／その種に水やり可）

### ② 掲示板
- Twitter風：アイコン＋ユーザー名＋本文、コメント数・いいね数、作成日時、報告ボタン。削除・報告可。
- **コメントのメンション機能は見送り**（将来検討）。

### ③ 収穫
- 自分が植えた種の一覧（タイトル＋ステータス：出品中／取引中）＋木全体の商品数
- 種タップ → その種に集まった商品一覧 → 商品詳細
- **「この商品を収穫する」** で取引フロー開始

### ④ プレミアム
- v1は基本後回し（課金設計と合わせて要相談）。プレミアム機能候補＝欲しいものリスト公開、ボーナス増量。

### ⑤ マイページ
- メニュー：個人情報設定 / 出品履歴 / 掲示板投稿履歴 / ぐんぐんについて / ブロックリスト / お問い合わせ / 退会 / ログアウト
- **プロフィール編集**画面
- 出品履歴：種植え・水やり両方
- 掲示板投稿履歴：自分の投稿・コメント

### 取引（やり取り）画面　※ホーム派生
- **受け取る商品／送る商品**の2つを別管理
- 色分け：受け取る＝緑、送る＝オレンジ。**スワイプで切替**
- ステータス：未受け取り／受け取り済み、発送済み／未発送。発送日を表示
- 各取引から メッセージ／受け取り報告／発送完了報告 → 取引詳細へ
- 受け取りの流れ：商品が届く → 受け取り報告 → 相手に通知 → お互いに評価
- 発送の流れ：商品を発送 → 発送完了報告 → 相手に通知 → 評価へ

## 6. アカウント・認証・個人情報（確定）

- **認証：メールアドレス＋パスワード必須**。
  - SNSログインは入れない（＝Sign in with Apple必須化の対象外で審査がシンプル）。将来SNSを足す場合はSign in with Appleもセットで。
  - パスワードのリセットは**メールのコード（Resend＋Supabase）経由**。
- **個人情報（姓名・電話・住所）は初回登録では入力させない**（離脱防止）。**初めての出品前に住所登録**を必須化する（発送に間に合わせるため）。

## 7. 通知（確定）

すべてプッシュ通知前提。送る対象：

- アクション：**水やり／収穫**
- 配送ステータス：**発送完了／受け取り完了**
- コミュニケーション：**取引メッセージ**
- 掲示板：**自分の掲示板にコメントがついた時のみ**

1. **課金設計**：肥料の金額・課金導線・プレミアム価格（1,500円は高い印象）。「現状のままだと成立しない」→ めたん様と詰めてから確定。実装は差し替えやすく。
2. **プレミアムの範囲**：欲しいものリスト公開などをv1に入れるか（課金と連動）。

## 付録：実装上の最重要ポイント
1. **ツリーのデータモデル（親ID・ルートID）を最初に固める。**
2. **「ノード離脱→子孫を新root化」を共通処理として1本化**（収穫・植え直し・削除で共用）。
3. 収穫は「一本道の玉突き」——道の全員に1発送・1受取が発生する単位でトランザクション設計。
4. 課金導線は後から差し替えられる形にしておく（金額・方式が確定前のため）。
